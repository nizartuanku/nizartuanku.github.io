Firewall Migration Config Review: what to send

Thank you for your order. We need two things: the configuration you are migrating from, and the configuration you plan to cut over to. This page shows how to export both per vendor and how to remove secrets first.

Scope: one migration, one source and one target device or context, up to 2,000 rules

Ground rules

  • Never send passwords, keys, certificates with private keys, or remote access. We do not log in to your systems.
  • Analysis runs offline on our own machine. Your files are deleted within 30 days of delivery.
  • Export the configuration exactly as it runs. Please do not edit rules by hand before sending, apart from removing secrets.

1. Export the source and the target

PlatformWhat to export
Cisco ASAshow running-config as a text file. Multi-context: one file per context you are migrating.
Cisco FTD (FMC-managed)show running-config from the device CLI, plus the access control policy report PDF from FMC (Policies > Access Control, report icon).
Palo Alto PAN-OSDevice > Setup > Operations > Export named configuration snapshot (running-config.xml). With Panorama, export the Panorama configuration as well and tell us the device group.
FortiGateSystem > Configuration > Backup (unencrypted). With VDOMs, tell us which VDOM is in scope.
Check PointAn export of the policy package and its objects (for example with Show Package Tool). Tell us the package name.

If you converted with a tool (RuleForge, the vendor's migration tool or another), include its conversion report too. It helps us see what the tool already flagged.

2. Remove secrets before you send

Search each file for the items below and replace the value with REMOVED. Keep the line itself, so the structure stays intact.

PlatformLook for
Cisco ASA / FTDpre-shared-key, key, password, secret, community, ldap-login-password
PAN-OS (XML)<phash>, <private-key>, <pre-shared-key>, <secret>, <password>
FortiGateEvery value starting with ENC, plus set psksecret, set password, set passwd, and certificate private keys
Check PointAny shared secrets or pre-shared keys present in the export

Optional: replace real public IP addresses with consistent placeholders (for example PUBLIC-IP-1), using the same placeholder for the same address in both files.

3. How to send it

  1. Put the source file, the target file and any conversion report in one ZIP file.
  2. Open the support chat on Whop and attach the ZIP, or ask there for a private upload link if the file is too large.
  3. Tell us the source and target platforms and versions (you already gave these at checkout; correct them if anything changed).

What happens next

  • We confirm the files are complete within one business day, or tell you exactly what is missing.
  • You receive the PDF report with risk-ranked findings, the cut-over checklist and verification tests within 5 business days of a complete set.
  • You can ask up to 10 follow-up questions in writing within 14 days of delivery.
